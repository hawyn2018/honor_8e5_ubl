# Native backend implementation status

Completed 2026-10-29, offline only. No device operations or firmware installation occurred.

Implemented `kbl_native_backend` against the existing controller ABI, with explicit provider callbacks, context-owned RAMFS/resources, cooperative job stacks and actual KBL ELF execution. The native part does not modify controller/fetch/host sources or the earlier barebox checkout. The native header is the provider/public-file ABI for the driver glue.

Implemented commands: `help el pwd ls cd mkdir touch cat cp mv rm echo hex stat true false exit sha256sum wc head tail grep hexdump xxd basename dirname printf`, plus slash-containing paths such as `./xxx` through the actual KBL ELF loader. This is the declared KBL ELF profile, not Linux/Android ELF or full POSIX sh. `exit` retains the context. Output uses backpressure without truncation. Immutable snapshots must be closed before stop; stop rejects open snapshots and job-stack/reentrant cleanup.

Validation: `test_native_runner.py` cross-compiles the real native code, context assembly, real ELF loader and SDK demo. The original native-unit result is `analysis/kbl-runtime-20261029/native-tests/validation.json`: seven groups and 1104 assertions per run pass. Both runs observed actual `MRS CurrentEL=1`; the EL2 PSTATE request was not realized by this Unicorn build and is explicitly not EL2 evidence. Each run ends with zero live provider allocations, no provider error, five execute-permission operations and one cache-provider call. The tests include `./hello` with argv, pause/resume, backpressure, allocation failure, immutable file reads, explicit suspended-job stop and unavailable execution permissions.

The final profile is general registers only: runtime, SDK C and handwritten program assembly must avoid FP/SIMD and interrupt-mask changes. The context is 112 bytes and saves X19–X30/SP/NZCV only. No FPCR/FPSR/vector/DAIF instructions remain in the context adapter. Both actual native-suite runs and the separate assembly round trip pass with CPACR_EL1=0. GPR/SP/NZCV restore, X18 remains unchanged, and existing FP/SIMD/DAIF patterns stay untouched rather than being switched. ELF and COFF context `.text` bytes are identical: 108 bytes, SHA256 `2e840072af925d18a1ef89a68b6c32e6e1858335b1ad7217933ee125f10ae4bb`. The former 228-byte SIMD context is superseded and is not the current supported profile. Original native-unit ELF SHA256: `38c7b071cf9790c750703ff0027d3fbe1b4c32f91529ddeead48bc2dc7c6685a`.

Independent historical review is in `review.md`. It found an initial cp-new-file publication window; the implementation now keeps the new node detached while copying and publishes only complete content. A regression test checks that suspended copy does not expose a new empty file or replace existing content prematurely. Its former SIMD-preservation paragraph is superseded by this final pure-GPR profile. Clang static analysis produced zero diagnostics in that review.

Remaining integration boundaries: actual UEFI pool/page permissions/cache/resource callbacks, EFI driver loading/unloading, original Fastboot transport and real phone execution are external to this native unit. Scheduling is cooperative, not hard timer preemption/fault isolation. Arbitrary raw UEFI resources allocated by custom programs are outside the native owned list and must be cleaned up by those programs. No full-shell, hardware EL2, phone boot or black-brick prevention guarantee is claimed from this test.

All compilation/test processes for this native work have finished. Further work belongs to the parent driver/transport integration.
