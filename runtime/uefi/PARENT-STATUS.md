# Native parent adapter

The parent adapter is actual freestanding AArch64 code, built as a position-independent module. `build_parent_shim.py` checks dispatch entry offset zero, a separate lazy-start entry, no undefined symbol, no dynamic relocation and no mutable section before generating `KblParentModule.kt`. The lazy services module is 4,668 bytes, SHA256 `9bb1b8f640b5db7b60aa7b6f61df8ce9d9c089fcccd17580e7da1010b6cb6ca9`. Its configurable report output defaults to `analysis/kbl-services-20261030/lazy-start/parent-shim`.

`KblPatcher.patch(canonicalPe, driver)` is a standalone API. The additive application facade controls its use; the preexisting patch engine is not edited by this component. EFI globals, native registration/response functions, download callback ABI and USB protocol/consumer relationships are derived from the input's code and data flow. No firmware RVA table is used.

The adapter appends `.textkbl` RX code, `.kblctx` RW zero context and `.kblimg` R/nonexecutable configuration/driver data. The `.text`-style code name matches the actual vendor SEC permission rule; RX flags alone were insufficient for the earlier `.kblrx` name. It preserves the original entrypoint, every original section mapping and original directory. Original Fastboot initialization and its registration-exit BL remain untouched. No KBL node, allocation, driver or USB initialization is added to that startup path.

`KblLazyEntryFacts` proves the original producer/consumer list, command-buffer parameter, 64-byte clamp and dominating NUL write, list-exhaustion branch, unknown-only edge and original shared FAIL BL. Only that unknown edge's B is redirected. Known original command handlers bypass the new gate entirely. The gate saves GPR/SP/NZCV and compares exactly the 12 bytes `oem kblstart` plus the terminating NUL, reading at most 13 bytes. This is the firmware's bounded complete C-string semantics; bytes following an embedded NUL in a raw USB packet are not claimed as preserved packet length. Other unknown commands restore registers/flags and branch to the untouched original FAIL BL with its original arguments. Successful matching uses paired real BL/RET calls, then returns to the same original dispatcher completion path. It performs no FP/SIMD or DAIF access and never fabricates a return LR.

Only the complete first START invokes original NativeRegister. Its producer/consumer-proved head, next, prefix, length and handler fields confirm each published node. Silent OOM receives an explicit FAIL; successful bits persist so a later START only fills missing entries. START's registered wrapper re-enters this same retry path. No static PE node is inserted into a firmware-owned allocation list. This retains the original allocator/free ownership contract. Registration is followed by driver loading and explicit START. A load failure preserves the successfully registered set without duplicating it on retry. `oem kblstop` and `oem kbloff` both use OFF.

If the original section table has insufficient records, the appender searches the existing header for a completely zero, directory/COFF-unowned gap before the old NT header. It copies only the active NT header/records and changes DOS e_lfanew. Old NT bytes, code, relocations, file offsets and section RVAs stay in place. Without sufficient verified space the input remains unchanged.

`removeAdapterDetails` validates the private trailing three-section layout, owned module/configuration/code/driver hashes and the hook, restores the original PE header/length and original instruction, and checks the reconstructed NT metadata. It accepts version-1 legacy .kblrx/B and .textkbl/BL initialization adapters and the version-2 unknown-edge B form. An unrelated original `.textkbl` without the private trailing context/resource pair is not treated as an adapter. Legitimate later edits to the original code/data survive removal; `fullyOriginal=false` reports that difference without rejecting text customization. The stored old-module length/hash permits removing compatible earlier modules rather than requiring their bytes to equal the current build. Standalone `patch` strictly verifies an old adapter using its embedded driver, then upgrades legacy names, hooks, modules or drivers; the first upgrade reports changed. Current canonical output remains byte-identical on repeated import. Application reimport follows canonical extraction, adapter removal, known legacy RX-name normalization, old-engine/text processing, then fresh append.

Only exact `oem kblstart` loads the EFI boot-service driver and binds the optional lightweight USB observer. Prefix lookalikes and extra start arguments are rejected before loading. `kblin`, `kbloff`, status, replies and ordinary Fastboot commands never auto-start the runtime. The driver image is cached across off; its native runtime/context is explicitly stopped. Failed startup cleanup retains its own image handle and exact off can retry unloading it. This also accounts for a nonnull handle returned with LoadImage security failure, as required by the [UEFI LoadImage contract](https://uefi.org/specs/UEFI/2.10/07_Services_Boot_Services.html#efi-boot-services-loadimage).

Control replies use DEFER_INFO and one original native final packet. The host retrieves immutable INFO pages with dedicated getvar calls. STORE and READ_OPEN envelopes receive native download arguments only when their ABI has been semantically proved. READ_OPEN uses the exact `env1:<16-hex-nonce>` argument; its nonce is checked against the staged KBLPUT01 envelope. Malformed or legacy arguments do not borrow native download state. Otherwise unavailable download ABI is reported while other control operations remain usable.

Binary fetch registrations are added only when the USB facts and original generic getvar handler are proved. The driver owns its observer/binding in its own loaded RW memory. START passes a copied 88-byte descriptor before the initial native ACK. A completed ACK plus a new normal command RX establishes a live idle witness; handler entry is not treated as proof of idle. The observer passes ordinary traffic through and never pumps a kernel job. A private KBL FETCH uses its own DATA/body transfer and the original final path. After a transport error the parent does not insert an extra FAIL into a possibly partial binary body. Off requests deferred safe observer restoration rather than freeing pending callbacks/DMA.

Non-KBL partition-size/has-slot queries and an existing native FETCH handler keep their original dynamically found routes. When no original native FETCH existed, the parent forwards a partition FETCH only after an explicitly successful START and a bound observer. It retains the full offset/length suffix. A failed START or OFF disables that fallback; loading the driver image alone does not enable it. An unbound max-fetch-size query follows the original generic handler rather than inventing private transport support. See `STORAGE-STATUS.md` for byte-I/O and validation boundaries.

Original offline evidence is stored in `analysis/kbl-runtime-20261029/parent-shim`; isolated repair evidence is under `analysis/kbl-fastboot-failure-20261029` and `analysis/kbl-boot-failure-20261029`. It includes actual SEC/DXE instruction execution, original registration/cookie/helper execution, synthetic Kotlin regressions, strict legacy upgrade/text tests and actual parent-to-driver nonce-envelope execution. Hardware observations for the separately prepared DC diagnostic are tracked by the parent task; they are distinct from an uninstalled application build. Custom programs remain cooperative, privileged, GPR-only programs; faults and non-yielding loops are not isolated. Conditional GCS overlay tests do not establish hardware GCS support or enablement.
