# hnubl 2.9.4：系统更新重启按钮标签同步

未完成 hnubl 保留锁态 OTA 时，原生手动重启入口已被门控跳转至 hnubl，但部分系统上的按钮仍显示“立即重启”。现场日志证明旧标签观察器调用 ART 堆枚举时发生 `iterateOverInstancesOfClass` 不可用错误，并将整个可选观察器撤销。真正的重启门控仍正常工作，因而出现文字和点击行为不同步。

## 按内容、功能与实际框架能力识别

- 使用系统实际支持的 WindowInspector、WindowManagerGlobal 窗口接口及必要的实际 View 列表发现当前窗口；按可用的方法签名选择能力，不再调用 `Java.choose`。
- 使用真实窗口 root 作为弱引用观察对象，支持 DecorContext 不持有 Activity 引用的系统，以及 Activity、Dialog 和动态创建的控件。
- 通过原生手动重启文字、语义资源文本、可见/启用状态和点击监听关系识别标签。父容器点击、子 TextView 显示文字的布局也使用同一规则，不固定荣耀混淆类名、控件编号、系统版本或地址。
- 生命周期和原生 ViewTreeObserver 的布局/窗口焦点事件触发合并异步刷新，覆盖文字变化和控件加入；只在前台活动窗口执行低频回退检查。
- 某条可选窗口能力失败仅记录诊断，其他窗口路径和生命周期观察继续保留。

## 状态与原生操作

标签后台只读取已有 `STATE` 协议。明确的 `ok=true,state=1` 显示“立即重启”；零、缺失或读取失败显示“继续流程”。标签刷新不执行 RESET、CONSUME、标记写入、重启或切槽。

原点击回调仍只执行一次，保留原参数、返回值及异常。原生下载/安装等其他文案接管同一控件后停止修改。实际授权、跳转、许可消费、延期切槽和重启仍由现有门控与厂商原流程处理。

排队的 resume/pause、STATE 返回及 UI 更新通过世代和弱引用隔离，避免从 hnubl 返回后被旧窗口任务覆盖。失焦停止状态查询；重复注入清理旧观察器、定时器和钩子。可选刷新或清理错误分别隔离，保持原生控件操作可继续执行。

## r2 修订

亮屏测试发现全局文本方法替换可能在真实 ART 调用中形成递归并导致栈溢出。r2 移除新增的全局 `TextView.setText`、`ViewGroup.addView` 和 `View.onWindowFocusChanged` 替换，使用实际 root 的标准视图树事件监听。事件通过后续消息合并处理，自身改字不递归进入刷新；暂停、关闭和重复注入时清理监听器。

应用与模块显示版本仍为 2.9.4，版本代码递增至 93。修订产物带 `-r2` 文件名，保留原先 2.9.4 的文件。提权、分区和实际 OTA 重启/切槽逻辑沿用原实现。

## 范围与验证

本版基于 2.9.3，应用和模块统一为 2.9.4。生产修改限于标签观察器，保留 2.9.3 的同版本缓存修复；重启门控、许可协议、Root 通道、提权、备份、解锁、分区操作、ABL/EFISP 修补器和 KBL 内容保持来源版本。

标签主机回归共 56 项，覆盖不支持堆枚举、不同窗口能力、资源内容、父子点击、Dialog、多窗口、原生异步改字、排队生命周期、状态读取和清理失败，并验证实际弱引用类型转换、原生视图树监听及事件合并。真机定向测试仅观察文字并读取状态，状态一的界面测试使用专门的展示提供者，实际许可保持原值；不点击重启入口，不执行系统 OTA 或切槽。交付验证记录区分主机结果和真机结果。
