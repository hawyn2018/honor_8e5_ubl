# 2.7.3 OTA companion

本版基于 2.7.1，支持页 UI/返回实现保持该基线。既有 ABL/EFISP 修补、F2FS/GPT 事务、备份和刷写内容不作功能改动。

## 使用与许可文件

OTA 页按钮安装内置 `hnubl_ota` KSU 模块，并请求即时激活。模块会仅重启软件更新应用以加载功能；不会由安装器下载/安装系统更新、重启手机或刷写分区。只有实际功能钩子全部初始化且私有标记通道通过验证，状态才为 `hook_ready=true`。安装后应核对这个结果，再依赖其 OTA 联动。

软件更新的全量包请求将使用 `recovery` 包类型，自动更新/夜间更新/自动下载的读取在更新进程内按关闭处理。重启倒计时在自动入口被阻断。用户点击更新完成后的重启入口时，缺失、空、0 或读写失败都不执行原入口，而跳到 hnubl OTA 页。

`/data/adb/hnubl/freeotaok` 是 root 私有、0600 的内部协议文件，hnubl 写入单字节 `1`。仅 FULL 保锁态 OTA 完整成功（包括原有写入/回读/公开完成清单）后写入；失败、仅刷写 EFISP 和导出不写入。标记与返回软件更新失败仅警告，不把已经成功的 OTA 改判失败。hnubl 不用该文件作为执行准入。

模块的消费操作先以同目录原子替换和 fsync 将许可落为单字节 `0`，再允许执行保存的厂商早期重启函数。只消费一次，后续原厂调用链保持；模块不另行模拟 reboot。自动或未分类来源不消费人工许可。新 payload 事件重置为 0；页面恢复及旧完成状态重放不会抹掉 hnubl 刚写入的 1。

## 运行范围与 Root 通道

自带 Frida 17.25.0 ARM64 运行时及 Java bridge，仅加载到已确认包名、UID 和进程名的 `com.hihonor.ouc` 主/子进程。其他应用不加载这些钩子，不注册全局 Zygisk/LSPosed 接口，不替换更新 APK。Root 代理使用应用私有文件系统 socket，校验 UID、包名和本应用签名历史，不打开 TCP 监听端口。普通其他应用不能使用该授权通道；这不是对具有 Root/系统权限的观察者作不可见性承诺。

初次安装模块需要现有 Root。模块运行后可为签名匹配的 hnubl 委托 Root，不要求再在 KSU 超级用户中单独授权。既有 KSU/Magisk su、内置提权及无线通道仍保留。真正命令只固定到一个提供者，提交后断线、125 结果未知等情况不跨通道重放。

## 兼容与性能

定位使用字符串语义、DEX 方法描述符、字面量参数寄存器关系、调用图和异步 Runnable 关联，无机型/厂商版本/混淆方法名/固定目标地址表。Android Settings 与 UpdateEngine 名称属于协议/ABI，不是厂商位置表。未知或歧义结构会报告未就绪；模块不会假报保护成功。旧版本仍应以真实 APK 验证，不能用改名测试代替旧版本覆盖。

Root 代理与监控器共用一个 Java VM。临时注入器在钩子加载完成后退出；钩子随目标 PID 存在。两个 socket 监听线程空闲时阻塞等待，没有循环探测客户端。APK 元数据缓存、APK SHA/解析器 SHA 双绑定的持久定位缓存、按需 DEX 扫描和指令对象释放降低启动峰值。运行/空闲轮询采用 1/2 秒间隔，优先从 ActivityManager 查询目标进程；API 受限时复用已确认 PID，定期以 `/proc` 回退发现，不把空列表当作身份凭据。状态未改变不写盘，激活请求 inode/大小/修改时间未变时不重复读取、解析 JSON。GC 仅在实际扫描结束/版本切换后执行一次。热更新保留 Root broker，并从不可变 DEX 快照替换 Controller，避免中断正在执行的命令或覆盖仍映射的文件。每次 Root 请求仍检查包名、UID、签名，不用身份缓存换取性能。

Java bridge 7.0.13 在临时构建副本中补入上游已合并的 [Android 17 ARM64 修复 PR 398](https://github.com/frida-packages/frida-java-bridge/pull/398)，修正 ArtMethod flags 定位和 ExceptionClear 回调常量池布局。另为 API 37 及以上加入本地、仅作用于更新进程的 JNI 反射策略：本模块不使用 JVMTI 的对象查找/类枚举能力，因此省去可选 JVMTI 插件加载，以反射读取方法和字段描述，避开加载插件引起的重型 ART 调试切换。这个本地策略与官方 PR 398 分别记录，不冒充上游已合并修复；[上游 PR 400](https://github.com/frida-packages/frida-java-bridge/pull/400) 提供了 live attach 调试切换问题的背景，其临时 native hook 实现没有合入本版。旧版系统保留原分支。Frida 运行时仍为 17.25.0，没有加入全局反优化操作。补丁、提交、许可证、各阶段 SHA-256 和未修改 npm 依赖锁均随源码保留；构建时强校验。

## 验证范围

构建会校验上游二进制、依赖锁、源快照和产物摘要。回归包括应用安装/标记/Root 提供者测试、代理协议和值检查、重启分流策略、类/方法改名与 DEX 顺序重排。真机仅做指定更新进程的钩子、只读全量包类型/开关、0 态标记访问及资源占用检查；不调用真实更新后的 reboot 入口、不下载安装系统 OTA、不调整或刷写分区。实际 OTA 后的完整重启由使用者验证。

2.6.11 审计：`BOOT-RECOVERY.md` 与 `abl-efisp-core/src/main` 的 53 个文件在 2.6.11→2.7.1 间完全相同。RecoveryFacts/KeyPolicy/SlotRecovery/AutoBootFailure 根据语义与数据流推导目标 RVA，旧成品按 core→KBL→Recovery 重建，追加空间按实际代码与 PE 对齐计算。没有机型/版本到厂商目标 RVA 的适配表；字符串、AArch64 指令模型、ABI 及控制流边界仍是必要识别条件。该更新修改生成的 EFISP，签名父 ABL 保持原样。
