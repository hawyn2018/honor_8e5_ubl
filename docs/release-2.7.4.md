# hnubl 2.7.4 发布说明与校验范围

版本号为 `2.7.4`，Android 和内置 OTA 模块的 `versionCode` 均为 `65`。本次以完整的 `2.7.3` 源码包为基准，保留原有应用签名身份。

## 设置与 OTA 界面

- 设置页的“支持”下方新增“许可证”，两个入口位于同一卡片，使用相同的整页进入、返回和手势动画机制。
- 许可证页包含可离线阅读的 GPLv3 完整中英双语文本。英文逐字使用项目现有 `LICENSE`；中文来源于 GNU 翻译索引列出的阮坤良译文，页面明确标注非官方译文及英文法律效力，并保留译者、来源及附加说明。
- OTA 按钮改为“升级前请点此处安装或更新模块”。先读取内置、已安装及待生效模块的 `module.prop`，仅内置 `versionCode` 较高时安装；已安装或待生效模块版本相同或较高时提示“已安装最新版模块，无需更新”。读取版本时使用字面值解析，不执行元数据中的 Shell 表达式。

## EFISP 兼容策略

按实际镜像中的功能和数据流定位政策分支，支持目标地址变化，不增加机型或版本地址表。仅在证明原有输入已读取、已有继续分支及输出关系时调整相关 AVB 低回滚索引和 OEM 版本一致性政策；原解析、实际 I/O、诊断及故障恢复流程保留。

AVB 元数据和 footer 的版本比较同样按诊断、字段来源和既有接受路径识别。调整版本门槛后继续执行真实解析，保留独立魔数、长度、算法及辅助数据验证。未能证明结构对应关系的分支保留原流程并报告覆盖范围。

该策略修改 EFISP 的运行行为，不把数据解析失败、缺少 DTB/DTBO、缺少固件协议或无效指针伪造成成功。父 ABL、XBL 及其他带签名镜像的内容保持原状。

KBL 的 ELF、USB、显示及分区协议适配调整数字版本门槛，实际协议长度、方法、内存及调用结果仍须匹配。普通系统引导、Fastboot 命令路由、KBL 惰性启动及 `kbladb` 显式启动 ADB 的机制保持。尚未启动 KBL 时不会提前运行 KBL 的文件、USB 或显示操作。

## 设备防回滚计数的范围

本版没有加入清零设备 OEM/QTI 物理防回滚计数的能力，也没有用修改镜像签名头的方式假称设备计数已归零。签名头中的 OEM/QTI 声明值、AVB 的存储索引及安全固件的实际最低版本是不同对象。

现有源码可定位 VerifiedBoot DeviceInfo 服务的读写边界，但 KBL 目前没有完整传递 AVB 存储索引及按分区映射的能力。样本的 `ReadRollbackIndex` 只读取 RAM 缓存；同一缓存中的写后读不构成持久化验证。当前证据没有证明可降低 OEM/QTI 实际设备计数的读写接口。`TZ_UPDATE_ROLLBACK` 属于更新请求，未证实为清零接口。本次不向设备计数发送写入请求，不改动带签名镜像的计数声明。

## 发布校验与测试边界

发布脚本先核验以下证据；缺少真实证据时停止发布，保留未验证状态：

1. 以 SHA-256 锁定的 2.7.3 基准、逐文件源码差异白名单，以及私钥、Token、本地日志和构建缓存排除。
2. OTA 模块源码快照、依赖锁、Frida 原始依赖、Bridge 官方补丁与本地受限补丁、模块内文件清单、模块 ZIP 与应用资源中的 ZIP 完整链。
3. 全量 App/Core 单元测试、原生兼容测试、驱动源文件和依赖清单、ARM64 EFI 驱动类型及打包后 SHA。
4. APK 包名、版本和签名身份；除 KBL 驱动、驱动 SHA、OTA 模块资源及新增许可证资源以外，原生库、内置 ABL、工具和提权资产逐字节不变。
5. 最终 APK 真机界面、许可证、模块版本策略及模块通道检查。
6. 从内置 ABL、当前槽位 ABL、现有 EFISP 分别生成候选并保留三条来源记录；若候选 SHA 完全相同，允许共用一次 RAM 验证。每个不同候选使用 KBL 的 `efi -bl` / `efi --bootloader` 从 RAM 执行，核对 Fastboot、KBL 与系统正常启动。同一最终驱动的 `kbladb` 只需一次实际验证。测试报告需绑定最终 Core JAR、驱动和源码快照；不刷写分区，也不写设备防回滚计数。

源码包内包含逐文件 `SOURCE-SHA256.json`。本地发行文件使用全新文件名，已存在的同版本文件不覆盖。构建脚本与发布脚本本身不连接设备、不刷写、不重启，也不向 GitHub 上传。
