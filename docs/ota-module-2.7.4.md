# 2.7.4 模块版本管理

OTA 顶部入口为“升级前请点此处安装或更新模块”。每次点击先校验内置 ZIP 的 SHA-256，再读取 ZIP 根目录的 `module.prop`，以其中 `versionCode` 作为模块版本依据，独立于应用版本和界面文字。

通过现有 Root 提供者只读查询 `/data/adb/modules/hnubl_ota/module.prop` 与 `/data/adb/modules_update/hnubl_ota/module.prop`。两处均存在时保留较高版本，避免将已安装或待更新的新版本覆盖成旧版本。内置版本较新或两处均不存在时才调用安装器；相同或已安装／待更新较高时提示“已安装最新版模块，无需更新”，不重复安装、降级或重新启动该模块。待更新位置和较旧待更新覆盖较高已安装版本的冲突会写入日志，便于用户核对 KernelSU 的待更新状态。

查询采用固定分段协议和 `cat`，不执行或 `source` 任一 `module.prop`，不依赖额外的分区工具或文本处理二进制。解析验证模块 ID、数字 `versionCode`，拒绝重复字段和截断查询；数字以任意精度整数比较，支持较大的后续版本号。未知、缺失、损坏的已存在版本或读取失败会明确报告，既不冒充“最新版”，也不覆盖版本未知的模块。

实际安装更新后，仍沿用 2.7.3 的即时启用流程：新 activation nonce、真实 `hook_ready` 状态和私有标记回路校验决定激活结果。单纯版本一致只说明本次无需安装，不额外宣称钩子已经启用。安装不会执行系统 OTA、重启手机或刷写分区；原模块更新应用钩子、Root 授权绑定、性能优化与 `freeotaok` 协议保持不变，详见历史说明 `ota-module-2.7.3.md`。
