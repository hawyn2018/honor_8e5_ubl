# hnubl 2.9.3：同版本 OTA 缓存提示修复

WebUI 关闭强制全量包后，新收到的检查响应原本会比较版本，但原生更新应用还可从数据库恢复已保存的同版本固件列表。原模块没有覆盖缓存路径，因此仍可能显示“发现新版本”。

## 功能定位与数据流

定位器从当前 APK 的固件 Cursor 列映射、完整固件列表读取、`Cursor.getCount` 统计和 `ContentResolver.query` 调用关系，找到列表与数量判断共同使用的原生 Cursor 查询适配器。固件 URI 来自该固件操作对象原生 URI 方法引用的实际静态字段；完整当前版本来自按固件版本功能识别的原生读取接口。初始状态取自实际新记录写入 `ContentValues` 的常量数据流。

映射随 APK 内容哈希及定位器代码身份重新生成；不内置机型、系统版本、混淆类名或地址对照表。定位不完整属于可选功能诊断，记录警告并保留更新应用原查询，不影响已就绪的重启保护。

## 一致的只读过滤

- 开关开启时直接执行原查询，保留强制获取全量包行为。
- 开关关闭且 URI、接收对象均匹配实际固件操作对象时，额外只读获取该组缓存。
- 只有全部记录都处于已证明的新记录状态、进度为零、完整目标版本明确同版或更旧，才将其数字行 ID 加入原查询 selection 的排除条件。
- 完整目标按 `targetBlVersionNumber` 的字段含义递归读取，不依赖存储 JSON 的 `a` / `b` 包装键。base、cust、preload 的局部版本不单独与整机完整版本比较。
- 列表和数量均继续使用同一原生查询及原生 Cursor；保留原 projection、绑定参数与排序，避免 UI 列表和数量不一致。
- 不删除数据库、偏好设置、下载包或变更安装状态。下载、暂停、校验、安装、待重启及未知状态全部保留；独立新增或未识别组件也保留。
- 进度读取沿用原生 `Cursor.getInt`：SQLite NULL 与原生初始记录一样读取为零。状态缺失和结构损坏则保留原记录。

新比较结果写入 `hnubl-ota` 日志的 `version_filter` / `cache_version_filter` 事件，缓存相同诊断去重。网络响应继续选择原生“当前已是最新版本”的原有状态分支，完整 JSON 中的长整数等其他字节保持。

此次仅调整 OTA 模块的版本识别、缓存查询和诊断，并更新应用与模块版本为 2.9.3。保留锁态 OTA 事务、Root 通道、提权资产、备份、分区刷写、ABL/EFISP 修补器及 KBL 运行时保持来源内容。

## 验证

验证覆盖三份真实更新 APK 的自动定位、混淆符号变化与缺失证据场景、版本比较/活动状态矩阵、原生查询参数和 Cursor 生命周期、WebUI 与原有保护回归。具体执行结果随本地交付验证记录保存；主机模型与定向缓存检查不等于实际系统 OTA 安装或切槽测试。
