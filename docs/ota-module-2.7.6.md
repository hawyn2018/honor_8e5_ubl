# hnubl OTA 模块 2.7.6

应用和内置模块均为 **2.7.6 / versionCode 67**。本版调整 2.7.5 的 WebUI“立即应用”行为。

| 点击时的软件更新状态 | 处理方式 | WebUI 结果 |
| --- | --- | --- |
| 正在运行，包括其子进程 | 重新激活模块并重启软件更新应用 | 等待新进程内钩子就绪后确认生效 |
| 未运行 | 重新激活模块，不主动打开软件更新应用 | 确认新 controller 已准备完成后，提示下次打开时生效 |

保存开关本身仍只保存用户选择，下次开机或点击“立即应用”才激活。已保存的有效开关状态继续在模块升级时保留。

软件更新是否运行必须在旧 controller 退出和清理目标进程之前捕获，避免把清理导致的进程退出误认为点击前就未运行。新的激活 ID、实际加载策略和 controller 就绪状态必须一致，写入配置快照本身不代表成功；软件更新正在运行时仍要求真实 `hook_ready`。

闲置时只保留原有的等待进程机制，不为确认应用设置而主动打开软件更新，也不增加高频后台轮询。下次用户打开软件更新时，新 controller 按本次激活的策略注入。界面区分等待打开、正在注入、真实错误和进程内已生效状态。

本版不改变 2.7.5 的全量包开关、数字/括号版本比较、原生“已是最新版本”路径、OTA 完成许可或 Root 通道。ABL/EFISP 修补器、KBL、提权、备份和分区写入逻辑保持原源码及载荷内容。版本 2.7.5 的发布文件保留。

验证使用设置生命周期与状态测试、WebUI 状态测试、浏览器模拟 KernelSU 桥、模块和 APK 构建、源码及 APK 载荷比对。测试不下载或安装系统更新，不重启手机或写入分区。
