# 2.8.11：正常启动数据流与可选恢复兼容

本次更新基于 2.8.10。独立修补工具同步为 fakebl 1.3.9；既有 Freedom 发行文件保留。

## 识别实际功能

修补仍以原镜像的状态来源、对象字段、命令参数、提交入口和控制流为依据，不使用型号、系统版本或固定 RVA 表。样本中发现的地址只用于回归证据，生产定位器不会把它们作为补丁地址。

状态分析补齐已识别编码的 CCMP/CCMN、MADD/MSUB 和 SIMD 指令写集。CCMP 更新条件标志，MADD 只改实际目标通用寄存器，MOVI 修改向量寄存器；这些语义不应被概括为改写任意状态对象基址。未建模指令仍保留未知效果，不直接推断为无副作用。

同一长函数可能同时构造初始化、错误和正常状态。优先保留原有严格来源匹配；只有严格匹配没有完成路径时，才从已证明的正常状态定义出发，沿没有字段覆写或对象基址重定义的路径追到相同对象的实际读取。兼容路径绑定已证明消费函数的真实输入布局：解锁字节位于输入起点，状态字段位于其后，并分别要求到调用点的唯一有效写入。getter 调用或栈槽重用使最初策略寄存器的历史难以归并时，不再强制该字节保持同一策略寄存器来源；实际状态字段、字节字段与唯一消费调用的关系仍需成立。其他路径的状态写入继续存在，不能冒充正常路线证据。

正常启动尾部仍需保持假回锁的 green 状态。此处也优先保留原严格匹配；兼容路径根据已证明的正常状态无覆写路径、实际零值成功清理、对象 context 及 formatter 的调用关系识别。allow 参数经 getter 或栈槽复用后改变寄存器历史时，不再把这段历史作为额外固定门槛。正常和错误返回及真实消费关系仍须区分，该尾部修改属于核心假回锁，不能以可选增强跳过。

自动切槽恢复不再要求处理函数恰好呈现某一固定写入数量，也不把某条 ORR 指令作为独立硬门槛。原生实现只标记当前槽，或另行清除对槽标记，都按实际属性读取/写入、共同提交后端、SetActive(false) 和重启关系识别。正常启动重试计数与手动 set_active 保留原行为。

## 必需功能与可选增强

| 类型 | 生成流程的处理 |
|---|---|
| 输入格式、映射及旧模块恢复信息 | 保持真实结构与来源核对 |
| 核心解锁与所选假回锁状态字段（含正常启动尾部） | 定位真实目标并完整修补，不能把缺失的核心修改算成成功 |
| KBL 注册入口、运行环境和 EFI 加载 | 必需功能；不以跳过 KBL 交付成功成品 |
| 可选键策略、自动切槽/故障恢复增强 | 分项分析；未匹配的可选项写明原因并跳过，继续已证明的其他功能 |

可选降级只跳过该项增强，不凭空构造挂接地址或伪造匹配成功。回滚更新、OEM/AVB 版本策略、独立解锁命令和故障上报等附加分析按项处理，日志写明未应用的部分。核心状态、所选假回锁、数据摘要/PSS 和 KBL 不归入此跳过组。已有 KBL、正常系统引导和原生 Fastboot 保持各自执行条件。

KBL 挂接继续按实际 Fastboot 命令调度、buffer 参数和返回值关系识别。调度及 lazy 入口的扫描范围由实际函数/控制流边界确定，避免寄存器调整或指令间隔变化被固定扫描窗口排除；KBL 运行时资源继续沿用上版。

恢复 scope 的外部入点分析只把满足 ARM64 指令对齐且映射到代码的值视为候选，避免把数据区的普通未对齐整数误作函数指针而排除本来成立的控制流。

## 资源与验证范围

沿用 2.8.10 的提权资产、Root 通道、内置父 ABL、备份/GPT/data 流程、OTA 模块及 KBL 运行时代码和资源。PSS 固定成功策略沿用上版，本轮没有借兼容性修改扩大其目标范围。

回归记录分别保存核心测试、不同 ABL 的实际导入/再次导入和 RAM 真机测试。KBL RAM 测试进入 Fastboot 后先显式执行 screenoff，再核对 KBL、文件传输和 EFI 加载；使用 efi/efi -bl 仅加载内存候选，不据此写入设备分区。源码说明不预填测试通过结果；最终交付说明应引用本轮实际记录。
