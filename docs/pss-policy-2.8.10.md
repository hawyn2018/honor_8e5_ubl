# hnubl 2.8.10：EFISP 共用 PSS 策略

本次发布 hnubl 2.8.10（versionCode 83）；Root 资产、OTA 模块与 KBL 运行时版本沿用上版。

生成的 EFISP 在本地共用 RSA-PSS 验证 API 上固定返回 0，作用于该入口的所有原调用者。固定成功是工具的本地策略接受，不是运行原密码学算法后证明签名有效。

## 策略范围

核心先提取待生成的 ARM64 PE，在完整状态初始化数据流中证明 OEMINFO 记录 0x82、384 字节签名来源、两个 descriptor 的同一签名缓冲区、共同调用目标、参数及返回零对应的既有成功路径。PSS 接口名、参数诊断、成功和失败消息的引用还需属于该函数的可达控制流。入口不是按机型、固件版本或固定 RVA 表选择。

对共同入口应用策略后，原 caller 的调用指令仍保留。所有经该 API 的调用都得到固定成功值；API 内部的 descriptor/参数读取、密钥及缓冲区准备、内存分配、RSA-PSS 计算和成功/失败/参数诊断均不再执行。原函数正文与消息仍留在镜像中，通用 logger 没有被静音。其他直接走独立 RSA、PKCS#1 或 AVB 路径的实现不因这项 PSS 变更新增修改；先前已有策略继续按原有合同运行。

此范围限于生成的 EFISP 的该共用 API。原始输入数组由 API 快照处理；父 ABL、XBL、TEE、持久认证记录、Root 提权资产、OTA 模块与 KBL 运行时不属于本次 PSS 实现修改范围。把生成镜像写入设备是应用另一个有备份/回读核对的既有操作，本策略本身没有设备 I/O。

## 入口与重复导入

保留适用的 BTI 入口前缀。存在 PACIASP/PACIBSP 时，早退配对相应认证操作，然后建立 W0=0 并返回；早退前不建立旧栈帧，不执行旧分配或参数内存访问。无 PAC 前缀时使用对应的无栈帧返回。保存 SP、LR 和被调用者保存寄存器的合同由入口指令与独立测试分别核对；本说明不把模拟器忽略 PAC/BTI 的行为当作硬件验证。

函数证据受当前节实际加载范围、后续入口及 CFG 约束。普通调用仅保留返回后的继续边，其 callee 正文不会提供本函数证据；RET/BR 终止该路径。第一条 RET 后仍可能有真正可达的冷块，不能仅按文本先后顺序判断函数范围。

再次导入保留原 caller、函数正文和消息引用。识别精确的已应用早退指令形态后，才从保存的后续正文恢复分析入口并重新证明身份。没有完整 PSS 证据时保留明确说明；有部分证据但接口关系不完整时报告错误，不借用相邻函数、死代码或同名字符串认定目标。新输出的真实产品 API 重复导入应得到稳定字节结果。

完整含 KBL/恢复模块的旧成品使用正式 `AblEfisp.patchWithKbl` 流程：先验证并剥离自有映射，再修补和重建。该过程可改变自有 KBL/恢复布局或完整性元数据。单独 PSS 修改范围由独立 analyze/apply 测试验证，不能把整个重建成品描述为只有一个字节范围变化。

## 验证范围与报告

新测试覆盖 builtin、233110/Magic8、BRT、APH136 四种唯一 PE 布局，旧 2.8.8/1.3.7 成品导入、两种核心模式、BTI/PAC/无 PAC 形态、边界与缺证据负例，以及原 caller 和声明范围外字节保持。233110 与 Magic8 抽取 PE 相同，不按两个独立布局重复计数。

本说明不预先记载测试通过或硬件启动结果。最终验收另行绑定源码/JAR/APK/候选镜像哈希、测试 XML、实际 RAM 加载及新启动日志。日志按父/child 同一启动归组；同一行两个 PSS 失败函数短语只计一条记录，empty-kpatch 与随后 verify-failed 属于同组。没有新保存日志时，保留“当前 live 启动尚未由持久化日志证明”的观测边界。
