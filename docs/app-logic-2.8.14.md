# 2.8.14：文件来源与权限

本次基于 2.8.13 更新应用层，版本 2.8.14 / code 87。已有发行文件保留。

ABL 刷写源、用于生成 EFISP 的上传 ABL、直接上传的 EFISP 分别保存。EFISP 相关上传入口放在 EFISP 功能卡片中；对一种来源的选择或替换不改变另一种来源。导出与仅刷写 EFISP 不要求提供没有参与该操作的 ABL 刷写源。

内置 ABL、上传 ABL 和上传 EFISP 的本地处理及导出先执行文件流程，实际读取设备分区时再使用 Root 通道。分区写入、备份与事务校验仍使用各自原有权限和成功检查；本次不将权限错误或修补错误当作成功。

修补适配边界将断言、栈溢出或链接错误转换为失败结果；取消、内存不足和实际刷写失败按各自逻辑报告，保留首个原因。诊断记录出错不掩盖原始修补错误，失败时保留原输入及已有成品。

设置页为支持与许可证提供左右一致的分隔线，并在下面单独提供自定义 su 路径卡片。自定义开关默认关闭，沿用既有 Root 选择；开启后使用用户保存的可执行路径，通过独立参数调用 `-c`，以实际 UID 0 证明为准。配置变化会使旧授权缓存失效；已开始的操作不会因路径变化自动重放。

使用方式：开启“使用自定义 su”，填写如 `/bin/666` 的绝对路径，点击“保存设置”，再到提权页检查授权。该文件须接受 `-c` 命令参数并实际提供 UID 0。开启自定义模式时，Root 任务及重启统一使用所选路径；无线调试仍可连接，但不会替换所选 Root 通道。关闭开关并保存后恢复原有方式。

提权实现及资产、内置父 ABL、OTA 模块、KBL runtime、分区脚本和修补核心沿用 2.8.13。实际构建、回归与资产一致性结果由交付报告记录。
