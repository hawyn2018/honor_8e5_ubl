# hnubl OTA 模块 2.7.5

应用和内置模块均为 **2.7.5 / versionCode 66**。本次以 2.7.4 为基础，仅更新 OTA 模块、版本标识和说明。提权实现、ABL/EFISP 修补器、KBL、分区备份与解锁刷写流程沿用 2.7.4。

## 使用方式

在 hnubl OTA 页面安装或更新模块后，进入 KernelSU 模块页面，打开 hnubl OTA 的 WebUI。

- **始终获取全量包：开启**：保留之前的全量包请求和可用更新行为，包含当前已安装版本。
- **始终获取全量包：关闭**：仍通过原全量包请求获取版本信息，再按照下表决定原系统更新应用的结果。

| 服务端数字版本与当前版本 | 括号内容 | 结果 |
| --- | --- | --- |
| 较高 | 任意 | 有可用更新 |
| 较低 | 任意 | 当前已为最新版本 |
| 相同 | 完全一致 | 当前已为最新版本 |
| 相同 | 不同 | 有可用更新 |

数字版本逐段按整数比较，支持型号前缀、全角括号和超长数字，不按字符串大小或有限精度浮点数比较。数字版本一致时比较完整括号内容，包括 SP/C/E/R/P 各字段；不推断括号内数字的大小。

首次安装默认关闭；由没有 WebUI 的旧版升级也默认关闭。后续升级保留已保存的有效选择。保存开关后不会立即改变当前软件更新进程，下次手机启动时生效；点击 **立即应用** 会重新激活模块，并只强制停止、重新打开 `com.hihonor.ouc`，不重启手机。

## 实现和兼容性

WebUI 使用本地静态资源和官方 KernelSU `ksu.exec` 接口，不依赖 CDN、在线字体或额外前端运行时。界面只调用固定模块脚本的 `status`、`save 0|1`、`apply` 操作。

持久设置保存在 `/data/adb/hnubl/ota-options.conf`。当前生效设置保存在带有激活 ID 的 `/data/adb/hnubl/ota-options.active.conf`。保存只修改前者；启动或立即应用才生成后者。controller 每次激活只读取一次，不增加后台设置轮询。

响应入口按 DEX 方法语义、协议字段、参数及调用关系定位。新增 `version_response` 必需角色，旧版缓存缺少该角色时重新发现，不复用不完整映射。当前固件版本优先从同次请求对象的完整版本读取，支持正常 BL JSON 与旧式 component 响应。

“当前已为最新版本”通过原响应完成入口的原生无更新状态进入原 `CheckResult → Handler → UI` 分支。只替换原 JSON 顶层状态字段，其余文本原样保留，避免长整数 ID 被 JSON 重新序列化改变。未知版本、未知响应结构或额外 COTA 等独立更新保留原结果并记录原因，避免隐藏尚未识别的有效更新。

界面仅在本次新激活 ID、实际生效策略和真实钩子就绪状态一致时确认立即应用成功。等待中不会仅凭脚本退出或配置已写入显示成功。状态查询只在立即应用期间短时执行，其余时间没有前端后台轮询。

原有自动更新关闭、倒计时保护、`freeotaok` 重启许可、Root 通道以及 hnubl 保留锁态 OTA 操作保持原逻辑。

## 验证范围

本次验证包含版本比较与响应处理测试、设置迁移和生效隔离测试、WebUI 状态测试、浏览器模拟桥交互测试、真实系统更新 APK 的离线语义发现和类/方法重命名及 DEX 重排测试，以及模块、APK、源码包的构建与内容校验。

浏览器测试使用模拟 KernelSU 桥，离线发现测试不等同于所有历史软件更新版本的真机运行结果。本次打包不触发系统更新下载、安装、设备重启或分区刷写。实际系统更新 APK 若改变了响应协议或原生状态流程，模块会在定位或就绪日志中显示具体覆盖情况。

接口来源见模块 `webroot/API-PROVENANCE.json`；WebUI、设置生命周期、版本比较及语义发现测试的运行方式分别见各自测试目录。
